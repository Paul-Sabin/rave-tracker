### Exact strings and events introduced (for Plan 04's `/admin/audit-log?event_type=...` checkpoint)

**New audit event types:**
- `auth.verification_send_failed` — written by call sites 1 (unverified login), 2 (registration), 3 (manual resend), 4 (expired-link auto-resend) whenever `send_verification_email` returns `False`
- `password.reset_send_failed` — written by call site 5 (`/forgot-password`) whenever `send_password_reset_email` returns `False`

**User-facing failure copy:**
- Shared constant (GET `/verify-email?send_failed=1` and manual resend): `"We couldn't send the verification email just now. Please try again in a moment."`
- Expired-link auto-resend (distinct, since `verify_expired.html` has only a `message` slot, not an `error` block): `"Link expired, and we couldn't send a new one just now. Please log in and use Resend Verification Email."`
- `/forgot-password` success text — **unchanged, confirmed byte-identical across success/failure/unknown-email:** `"If an account exists with that email, we've sent a reset link."`

## Decisions Made

- Kept the `auth.verification_resent_auto` event name for the expired-link *success* path unchanged (an established event type; renaming would break historical audit queries) — only the new failure branch got a new event name (`auth.verification_send_failed` with `trigger: expired_link_auto_resend` in details).
- Test failure-text assertions target `"verification email just now"` rather than the plan-suggested `"couldn't send"`, because Jinja2's autoescaping renders the apostrophe as `&#39;` in the actual HTML response (verified by manual response inspection during test debugging). This is a test-assertion adjustment only; the user-facing copy itself is exactly as specified in the plan.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Test assertion string didn't match Jinja2's autoescaped output**
- **Found during:** Task 2 (writing `tests/test_auth_routes.py`)
- **Issue:** The plan's contractual assertion text `"couldn't send"` (with a literal apostrophe) never appears in the rendered HTML, because Jinja2 autoescapes `'` to `&#39;` by default. Both `test_resend_failure_shows_error_text` and `test_verify_email_page_shows_error_only_with_send_failed_param` failed on first run against the real rendered response.
- **Fix:** Changed the test's `FAILURE_TEXT` constant to `"verification email just now"`, a substring of `VERIFICATION_SEND_FAILED_MESSAGE` that contains no apostrophe, so it matches the actual rendered HTML regardless of escaping. No change to the message text itself or to `routes.py`.
- **Files modified:** `ra-tracker/tests/test_auth_routes.py`
- **Verification:** Both previously-failing tests pass; full suite (44 tests) green.
- **Committed in:** `6bb6c29` (Task 2 commit — the fix was made before the first commit of this file, so no separate commit exists)
