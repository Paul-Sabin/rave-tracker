<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app process -> Brevo HTTPS API | A long-lived secret (`BREVO_API_KEY`) crosses this boundary in a request header on every send |
| app process -> log sinks (stdout, Sentry, Better Stack) | Log records leave the process and are retained by third parties; anything interpolated into them is disclosed |
| Railway environment -> app process | Credential values arrive as env vars; the app must not weaken which credential it accepts |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20.1-01 | Information Disclosure | `email_sender._send_via_api` logging (lines 95, 122, 125) | mitigate | No log statement interpolates `api_key` or `config.email.password`; `test_api_key_never_logged` asserts the key value is absent from `caplog.text` on the 401 path (Task 1 test 9, Task 2 acceptance grep) |
