<objective>
Stop the web layer from reporting success for mail that was never sent. Five call sites
currently discard the boolean returned by the send functions; make every one of them
branch on it, surface the failure to the user where that is safe, and always record it
distinctly in the audit log.

Purpose: SC-2 (a failed send surfaces an error instead of "Verification email sent!"),
SC-3 (a failed send is distinguishable in the audit log), and the routing half of SC-4
(the password-reset call site gets the same treatment, adapted for its
account-enumeration constraint).

  `send_failed` query param, 2 new audit event types
- `ra-tracker/tests/test_auth_routes.py` (new) - 9 route-level tests
