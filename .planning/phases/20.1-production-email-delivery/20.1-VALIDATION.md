## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | pytest 9.1.1 (installed from `ra-tracker/requirements-dev.txt`, never `requirements.txt`) |
| **Config file** | `ra-tracker/pytest.ini` (`testpaths = tests`, `pythonpath = .`, `addopts = -q`) |
| **Quick run command** | `cd ra-tracker && ./venv/Scripts/python.exe -m pytest tests/test_email_sender.py tests/test_auth_routes.py -x` |
| **Full suite command** | `cd ra-tracker && ./venv/Scripts/python.exe -m pytest` |
| **Measured runtime** | 12.3s for the 26-test baseline (measured 2026-08-22); expect ~15s at 44 tests |

Notes:
- `./venv/Scripts/python.exe -m pytest` is the verified invocation on this Windows box;
  plain `python -m pytest` works when the venv is activated.
- No new test dependency is added by this phase. `unittest.mock` and `asyncio` are stdlib,
  and the async senders are driven with `asyncio.run()` rather than pytest-asyncio.
- `tests/conftest.py` pre-seeds `os.environ` before importing any app module, which is what
  makes it structurally impossible for a run to reach production Postgres or send real
  mail. Neither new test file may modify it.
